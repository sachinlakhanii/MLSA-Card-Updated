# Project guidance

This is a private plain HTML/CSS/JavaScript studio. Keep credentials out of source control and validate all API input in `lib/validate.js`. Public output must not mention the studio.

Authenticated handlers are `api/members.js`, `api/member.js`, `api/publish.js`, and `api/delete.js`. Use `lib/api.js` for authentication and `lib/storage.js` for website files; production uses GitHub and local testing uses `LOCAL_SITE_DIR`. Keep create/update/delete behavior covered by `node scripts/test-members.js`. Client member management is in `assets/js/members.js`. Do not introduce a database, framework, or build step.

GitHub is optional. Validate usernames in `lib/validate.js`, save `github` as an HTTPS github.com profile URL or an empty string, and accept old records without it. `assets/js/handles.js` handles the field and the wide footer; absent handles must leave no icon or divider. Keep the social image layout unchanged. Run `node scripts/test-github.js` for validation/profile checks.

Font Awesome Free 6.7.2 core/brands CSS, the brands WOFF2, and license are self-hosted under `assets/vendor/fontawesome/`. Preserve the upstream license and comments. Exports must explicitly load the brands font and await fonts before rendering. The public site owns its own vendor copy; publishing must never write vendor files.

Cards are Dark-only in the studio. Publishing retains both website variant URLs with the same Dark artwork through `renderCard(scale, 'wide', theme)` without mutating the selected layout/theme. Send the same Dark PNG as `files.cardAlternate`; the API derives `card-dark.png` and `card-light.png`, preserves `card.png`, and sets `cardThemes`. Keep the full request below 4,400,000 bytes, including base64/JSON overhead, and keep image/size validation in `lib/validate.js`. Preserve legacy single-card requests and unchanged social-image rendering.

Keep the preview's photo proportions in exports: `assets/js/export-photo.js` bakes the cover crop/object position into the off-screen clone before html2canvas renders. Do not stretch the original photo to the frame or overwrite editor state. Check geometry with `node scripts/test-export-photo.js` and verify both portrait downloads and wide publishing when changing this path.

The local server uses a fresh API worker per request to reload transitive templates. Check the publish protocol before uploads; updates of themed records must provide both cards and must never silently downgrade them. Legacy single-card requests remain supported for records without variants. Member assetVersion revisions keep updated images fresh. Run scripts/test-members.js through the local worker.

Branding: use MLSA SZABIST Islamabad and Microsoft Learn Student Ambassador(s), with the supplied assets/img/microsoft_learn_student_ambassador_4k_transparent.png badge, displayed through assets/css/brand.css without cropping or stretching. Preserve existing member IDs and profile links. Card headers group the badge, Microsoft Learn title and campus text without overlapping the SZABIST logo.

Card-only design: Wide uses the supplied Social Cards shield/building assets and SVG decoration; Portrait uses the supplied Code Cards artwork. Presentation lives in assets/css/card-design.css and assets/js/card-artwork.js, card-palettes.js and card-presentation.js; self-contained source artwork is in card-art-assets.js. Match palettes to the existing Team field, with MLSA SZABIST as fallback. Keep team labels live, rather than baked into the pill. Both layouts use Dark artwork; do not reintroduce a White card option. Preserve legacy theme inputs and variant filenames for compatibility. Self-host Montserrat and retain its OFL license. Wide stays 1080x1012; Portrait stays 1080x1700, with extra height inserted only in a plain gradient area. Interface headers and the social image keep the 4K transparent badge; do not derive the social logo from the card DOM.

Verification card backs use the shared cardBackSvg/profileUrl helpers in the studio assets/js/verification.js. Keep QR codes self-contained, with a white quiet zone in both themes and the configured SITE_URL/profile/<slug> target. Publishing generates Portrait backs in both themes on the server without additional image uploads. Wide cards are front-only. Portrait PNG downloads combine the back on the left and front on the right at identical dimensions. Preserve the MIT license for the vendored QR encoder. Test with node scripts/test-verification.js in the studio and decode actual exported QR images when changing artwork.
